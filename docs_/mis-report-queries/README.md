# Standalone MIS report queries

These MySQL 8 queries reproduce the rows generated by the four Jasper MIS
report templates. Each file is self-contained so it can be run independently
for verification or exported from a SQL client:

| Report code | Query |
| --- | --- |
| `MIS_TICKET_SUMMARY_RPT` | [`mis_ticket_summary_rpt.sql`](mis_ticket_summary_rpt.sql) |
| `MIS_RESOLUTION_TIME_RPT` | [`mis_resolution_time_rpt.sql`](mis_resolution_time_rpt.sql) |
| `MIS_CUSTOMER_SATISFACTION_RPT` | [`mis_customer_satisfaction_rpt.sql`](mis_customer_satisfaction_rpt.sql) |
| `MIS_PROBLEM_MANAGEMENT_RPT` | [`mis_problem_management_rpt.sql`](mis_problem_management_rpt.sql) |

## Usage

1. Open the required file and edit only the `SET` values at the top.
2. Use `NULL` (or `''`) to disable an optional filter. The category and
   subcategory parameters contain the text stored in `tickets.category` and
   `tickets.sub_category`, despite their API names ending in `Id`.
3. Run the entire file against the same MySQL database used by the application.
4. Export the final result grid as CSV/XLSX, or use the MySQL CLI, for example:

   ```bash
   mysql --batch --raw --default-character-set=utf8mb4 \
     -h HOST -u USER -p DATABASE \
     < docs_/mis-report-queries/mis_ticket_summary_rpt.sql \
     > mis_ticket_summary.tsv
   ```

The supported interval values are `DAILY`, `WEEKLY`, `MONTHLY`, `QUARTERLY`,
and `YEARLY`. Dates are inclusive calendar dates: the queries implement the end
date as an exclusive boundary at midnight on the following day. Defaults match
the report definitions: `2026-07-01` through the current date, grouped daily.

`MIS_PROBLEM_MANAGEMENT_RPT` intentionally ignores category, subcategory, and
interval. That is also how the application report works: it returns root master
tickets and their current child counts.
